# POSIX 保留句柄存储审查交接

[English](private-storage-review.md) | 中文

## Status

新增 `./private-storage` 候选在发布前仍需独立原生源码审查，以及实际受支持文件系统上的验收。它独立于现有 flock 绑定和 Landlock 启动器；两者的 C 源码及行为保持不变。入口按需加载，缺少后继版本二进制时直接失败，不会改选旧包。候选包族版本为 `0.1.3`。

## Review inputs

原生实现为 [private-storage.c](../packages/entry/src/private-storage.c)，SHA256 为 `f0648994ab27e95d0496829f49d85f9012ef7529f749a794e9b94bcbda66e665`。[带类型的按需入口](../packages/entry/src/private-storage.ts)描述其不透明操作。[原生测试](../test/private-storage.test.js)使用 [Worker 夹具](../test/private-storage-worker.js)、[模拟读取失败的动态库](../test/private-storage-read-fault.c)及[独立系统调用校验器](../test/private-storage-syscall-oracle.c)。系统调用校验器绝不报告提供方或持久性验收通过。

以下方面仍需独立审查：

- 资源引用、环境清理、终结器顺序、关闭前失效，以及 GC 或 Worker 终止后的描述符释放
- 字面组件校验、保留的祖先绑定、禁止跟随链接的打开、完整观察，以及独立的只读源文件和私有目标准入
- 同一父目录下的排他发布、禁止回退到普通 rename，以及按身份校验的未发布对象清理
- 同一父目录下的非阻塞管理租约、现有锁文件准入、完整读至 EOF 的当前记录及有界生成记录替换
- 已确认的部分 I/O、终止性失败、发布不确定性、同步和晚期释放回执
- 原始字节、对象及访问策略保留，不进行修复写入，也不把目标硬链接到源对象

## Native operation scope

目录能力保留每个已准入祖先。源文件以只读方式打开；源策略允许共享可读目录和普通源硬链接。私有目标要求当前用户所有权、精确的仅所有者权限、已准入 ACL 策略，以及受支持的可写持久文件系统。不会收紧或修复现有权限。`openPrivateRecord` 对只读当前记录句柄施加私有叶子准入；上层记录读取器保留独立的 64 MiB 上限并计算摘要。共享安装源文件流仍要求事先独立确定的预期摘要。

Linux 目标观察报告 ext 文件系统族、XFS 或 Btrfs。`0xef53` 魔数不能区分 ext2、ext3 和 ext4；回执不会将其特指为 ext4。实际排他重命名和同步支持由操作检查，不受支持即失败。Darwin 目标支持限定为 APFS，并检查扩展 ACL 为空。Overlayfs 和 tmpfs 可作为只读源文件系统，但在创建前会被拒绝作为私有目标。没有诊断选项会放宽该提供方策略。

发布在同一保留父目录下使用 Linux `renameat2(RENAME_NOREPLACE)` 或 Darwin `renameatx_np(RENAME_EXCL)`。Linux 要求文件 fsync、排他重命名、父目录 fsync 和最终绑定校验。Darwin 要求文件完全同步、排他重命名、父目录 fsync、对保留文件再次完全同步，以及最终绑定校验。系统调用序列成功不等同于实际断电保证。普通读取可能更新 atime 或产生操作系统审计事件；保留检查不会通过写入原文件来恢复这些副作用。

POSIX 目录描述符无法阻止任意同用户进程重命名目录。命名空间修改要求调用方持有协作管理租约并符合可信所有权模型；提供方检查保留绑定，并拒绝不安全清理。关闭、GC 和环境拆卸仅释放资源，绝不发布、删除名称或选择运行时。

## Executed checks and remaining rows

Linux x64 Node24.19 使用稳定 Node-API v8、官方头文件、C11、将警告视为错误及隐藏符号可见性编译了新插件。GCC 静态分析和 UBSan 在已执行检查中未报告问题。已编译 glibc 插件的 SHA256 为 `1082d838edf07ed4b530eeb00d962cd430aa9f4cda28669490a40ada072a011e`。

较早检查点的原生套件在 tmpfs 上记录39项，并在 overlayfs 及 UBSan 下单独执行：19项通过，20项因这些文件系统不满足私有目标准入而明确不可执行。通过项目包含只读/硬链接源保留、有界顺序读取、源修改拒绝、禁止跟随链接和类型检查、保留父目录生命周期、能力隔离、实际 GC/Worker 描述符释放，以及执行时关闭行为。模拟的短读取、中断和错误注入单独标记。独立 rename/fsync 校验器仅为诊断。

20项目标测试仍未执行：目录创建/同步、输出发布、冲突/中止、私有记录读取、租约竞争与准入、创建后残留、记录替换及六种拒绝情况、已关闭或仅源文件能力的拒绝、租约 Worker/GC 释放、两个 Worker 的写入竞争，以及输出 Worker 拆卸。必需的原生 CI 设置 `PRIVATE_STORAGE_REQUIRE_DESTINATION=1`，将目标准入不可用转为失败。跳过的项目不算验收通过。

现有 flock 和包元数据套件在本地构建的 glibc 插件上通过50项测试。完整校验器构建因缺少 `musl-gcc` 停止；glibc 校验器已构建并使用，但 musl 生产插件/校验器尚未构建。Linux ARM64、两种 macOS 架构、实际 APFS 行为，以及所有后继包的独立安装消费者项目仍待完成。原生流式大小上限、最终公共产物闭包及全部应用消费者各自需要证据；这些本地检查不能完成相应验收。

## Bounded materialization and process observations

最新 Linux 套件及 UBSan 重复运行各记录63项：24项通过，39项明确跳过。37项需要已准入的持久私有目标，另外2项需要真实 Darwin 进程出生观察。上述旧检查点的19/20项结果仍仅描述旧字节；不能替代后继版本验收。原生环境清理、Worker/GC、只读源保留、受限读取和平台拒绝具有本地证据，持久目标、macOS 及独立 C 审查仍未完成。

`openChild`、`createPrivateChild`、`openPrivateOutput`、`listDirectory` 和 `observeCapacity` 保留目录祖先，并分别记录发布、同步和释放。枚举最多100000项，零只允许空目录；变化或超限直接拒绝，不截断后声称完整。输出审计保留1 GiB流式上限，不授予64 MiB控制记录替换权限。容量只报告文件系统当前可用事实，不是全局预留；部分写入或审计失败后不得封存。

`observeProcessBirth(pid)` 仅支持 Darwin，只接受当前进程或内核确认的同所有者直接子进程。它在重复观察所有权及出生信息后返回原始 `ri_proc_start_abstime` 与启动会话 UUID。这是观察而非保留式退出监视器：失败、ESRCH 或 PID 复用不能生成已确认退出回执。Linux 明确拒绝此能力。Darwin 构建链接 libproc，真实 macOS 编译和运行仍待验证。原有九个存储操作函数体与保留的 `3a348e1f…` 检查点完全一致。

## Current-record switching gap

后继版本新增 `acquireLease` 和 `replacePrivateRecord`。前者使用保留的私有 0600 单链接锁及非阻塞 flock；释放时不会删除锁。后者要求相同私有父目录、有效租约、已完整读至 EOF 且观察不变的当前私有记录、已同步的 0600 暂存记录，以及独立的 64 MiB 上限。它仅对生成的控制记录执行相对 `renameat2(flags=0)` 或 `renameatx_np(flags=0)`，不会用于已安装代码或原始配置文件。不可变产物的排他发布操作保持不变。

创建错误保留已确认或不确定的条目创建、已观察对象事实、绑定检查、实际描述符释放及目录同步情况。失败的打开不会删除未返回能力的条目。上层生成记录所有者绑定固定名称白名单，在调用方持有的租约下先校验当前完整观察、摘要及应用版本，再创建暂存对象。回执独立记录替换事实、内容校验、持久性和释放。这是协作式串行比较与替换，不能防御恶意的同用户写入者。

这些原语尚未完成应用事务。消费方仍需独立审查的前代/操作关联、当前引用发布顺序及中断恢复。原始 Profile 文件保持在写入授权范围外。冷启动及在线读取、编辑器导入、HMR、回滚和打包原生验收均需独立集成证据。

## Public review delivery

当发布已获授权并完成验证时，本文档和精确源码/测试补丁可随现有源码 PR 提交。本地工作树路径不是已发布产物，也不是用户可访问的 PR 链接。在审查者针对精确已发布源码记录结论之前，审查状态保持待定；在匹配的原生二进制执行全部必需项目之前，平台验收仍保持待定。
