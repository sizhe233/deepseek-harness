# Agent Note: 工作台运行时兼容

Status: implemented

[English](2026-09-11-workbench-runtime-compatibility.md) | 中文

## 问题

工作台部署使用按 Session 路由的 OpenCode 请求、不透明 Responses 压缩内容，以及官方 0.1.5-rc.1 无法直接完整读取的历史日志。文件预览插件也参与 Chat 文件打开流程。即使主应用能启动，丢失这些能力仍会破坏已有会话。

## 决策

本地运行时采用官方 `dsh-v0.1.5-rc.1` 的完整依赖，并且仅对这个版本应用由源码维护的兼容修改。工作台补丁 manifest（元数据清单）记录原始与替换产物的 SHA-256。补丁器拒绝未知运行时或产物。

pi-ai 适配器从实际 Session 派生 `x-opencode-session`，保留结构化流错误，并为跨模型工具历史补齐必要的推理文本。LLM（大语言模型）与压缩包保留原生 Responses 压缩及其不透明回放项。这些传输细节不会引入新的 agent（智能体）框架，也不改变任务委派策略。

格式读取器保留全部原始消息、工具结果、用量样本与带时间戳的流片段。字段兼容的一次性描述符使用当前结构版本。旧的可续接描述符保留为历史记录：迁移不会补造缺失的人设或工具限制，也不会授予恢复权限。

Chat 将普通文件交给原生 Sidebar，并允许现有预览提供方处理结构化表格和通过能力检查的外部文件。提供方拒绝访问时仍保持拒绝。独立 Connection RPC 处理器通过所属上下文解析共享 Web 服务载体，并由调用方负责 dispose（资源释放）。

## 考虑过的替代方案

**直接升级未经修改的包。** 隔离会话语料和插件组合暴露了迁移失败与兄弟上下文 RPC 载体问题。启动成功不足以证明保留了已部署行为。

**使用含旧 Host 包的回退目录。** 混合服务身份与事件约定会使候选不可复现。安装目录只包含一个精确的 Host 版本。

**提升全部旧 subagent 描述符。** 旧的可续接记录缺少当前 schema 要求持久化的权限信息。保留历史且不补造权限，维持了已有恢复边界。

## 结果

本次部署维护小范围源码分支和不可变编译补丁。协调器同时切换运行时、Profile、会话、配置和派生缓存。由于旧版无法读取新增 V3 数据，回滚会将其单独保留。

历史验收覆盖了该运行时代次的模型请求、迁移、RPC、GUI 行为和已录制的 Web 流程。这些结果不能确立新候选的验收。每个候选都遵循[公开 fork 验收流程](../../../../workbench/README.zh.md#acceptance-and-release)；私有部署证据保留在本仓库之外。性能测试将 Session 冷打开与提供方推理耗时分开比较。
