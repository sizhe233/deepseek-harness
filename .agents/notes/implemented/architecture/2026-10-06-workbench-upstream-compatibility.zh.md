# Agent Note: 在上游 API 变化中保留 Workbench 行为

Status: implemented

[English](2026-10-06-workbench-upstream-compatibility.md) | 中文

## 问题

受维护的 fork 在官方 Host 上扩展了持久 Responses 检查点、可选外部插件入口、可编辑 MCP 配置和进程生命周期修复。上游改变了 Session 写入版本、设置持久化、HMR 归属和 SDK 接口。文本合并成功不能证明这些行为仍然存在。

## 决策

fork 合并官方历史，并在 [workbench](../../../../workbench/upstream-compatibility.json) 中保留逐路径兼容清单。提供方原生压缩沿用已准备的适配器代次，并在历史 Session 转换中保留不透明检查点的全部字段。现代工具消息和图像卸载投影使用上游表示。其他路由的适配器会拒绝不支持的检查点，而不是将其展平或丢弃。不透明检查点块扩展已有持久化消息联合，因此 fork 使用 [V5 后继](../../../../docs/upgrade-guide/v0.2.1-alpha.1/session-format-v5/guide.zh.md)，而不改变已接受的 V4 含义。V4-to-V5 迁移保留普通载荷，仅提升通过校验的历史检查点扩展；已接受的 V4 历史保持不变。

MCP 编辑使用当前从 Config 派生的表单和 Profile 持久化。秘密值仍为只写，修订检查拒绝过期保存，持久化失败会恢复运行时配置及启用状态。Client 在上游功能自有设置旁保留独立 MCP 页签。旧控制条目和已保存的命名空间键具有严格限定的迁移。

精确配置监听归属 `dsh-hmr`；fork 保留文件层级和平台就绪行为、相对路径注册及失败通知。Linux 取消结合上游控制管道和直接进程停稳逻辑，并要求进程计数观察在范围建立后发起。PowerShell 启动必须收到已验证的受控提示符，包括自定义参数选择 stdin 引导的情况。

可选 E2B 家族保留普通文件系统、shell、PTY 和 LSP 行为。其 SDK 无法提供新增的独立子进程控制通道，因此会在分配远程工作之前拒绝该请求。终端尺寸调整使用 SDK；不支持的活动观察保持未知。真实提供方验收属于单独的凭据检查。

继承工作流在官方仓库限制条件内保留完全相同的上游事件条件。Fork CI 使用只读仓库权限运行、打包候选产物，并且不会部署。构建后的重启准入和图像中继仍是可选且绑定哈希的桥接；未知 bundle 会在写入之前被拒绝。外部插件验收必须使用同一份候选字节。

真实 PowerShell 编码用例在独立文件屏障之后读取子进程产生的 scrollback，不将已结算的 viewport 当作命令完成。它验证 UTF-8 输出和进程清理，而不改变产品时序。专用 CI 配置独立于上游 Windows 排除项，要求在 Linux、macOS 和 Windows 上执行这些真实 PowerShell PTY 用例，并在 PowerShell 不可用时失败。目录切换用例使用实际文件系统根目录，使同一断言适用于 POSIX 根目录和 Windows 驱动器。[已复核的修复](https://github.com/sizhe233/deepseek-harness/pull/4)记录其确定性对照。

## 考虑过的替代方案

**将 fork 重置到上游。** 这会丢失本地行为，并移除判断补丁是否已有等效实现所需的证据。

**在新包旁保留旧运行时。** 混合服务身份和 Session API 会掩盖不兼容，也不能产生可复现的候选产物。

**将编译或 Host CI 当作插件验收。** 二者都没有验证独立维护的 Client 代码、已有设置迁移、可选运行时桥接或真实提供方行为。

## 影响

每个保留或适配的补丁都需要针对性行为证据和集成候选检查。已发布 Session 代次保持不可变。候选产物和测试结果标明确切源码修订；仓库引用检查仅允许三个带版本的 Workbench 机器记录在已审查字段中使用完整提交标识，正文仍使用发布标签和 PR 引用；跳过或未执行的检查必须明确保留。生产安装、用户数据迁移和付费提供方探测需要各自授权。
